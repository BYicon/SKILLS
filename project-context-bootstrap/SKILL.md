# 项目上下文初始化

为仓库创建或系统重建一套轻量、耐用的 AI 首读文档体系。先审计真实代码结构，再产出少量高信号文档，让后续会话优先读文档，只在需要时回到源码。

## 使用时机

- 刚接手一个新仓库，需要建立 AI 可读的统一入口
- 现有 `AGENTS.md`、`CLAUDE.md`、`docs/` 长期失修，用户要求结合真实仓库系统重建项目上下文与统一入口
- 每次新会话都要重复摸底，希望把仓库事实沉淀成稳定上下文
- 需要把真实活跃模块、占位区域和系统主链路明确标出来

## 不适用场景

- 只是修一个局部 bug 或补一个小功能，不需要整理整套首读文档
- 仓库已经有高质量且结构清晰的 AI 文档体系，只需局部微调
- 仅审查或局部整理现有指令的冲突、冗余，或排查加载不生效；如环境提供 `agents-md-optimizer`，该类请求由其处理，本 skill 不要求安装或联动它
- 当前任务重点是功能交付，而不是建立统一的项目上下文入口

## 工作流

### 1. 先审计仓库，再动笔

只读取足够建立全局认知的文件：

- 根目录 `README*`、`package.json`、工作区配置、应用/包目录
- 现有 `AGENTS.md`、`CLAUDE.md`、`docs/`
- 活跃应用或服务的关键入口文件
- 只有在当前优先级依赖近期变更时才查看最近提交

在确认这些事实前，不要先套通用模板：

- 哪些应用是真实在跑，哪些只是占位或脚手架
- 哪些共享包被真实使用
- 现有文档应该合并、修订，还是本来就缺失

### 2. 产出最小但耐用的文档集合

除非仓库已经有等价结构，否则优先维护下列文件：

- `docs/PROJECT_CONTEXT.md`：首读项目概览
- `docs/ARCHITECTURE.md`：模块边界、运行形态、主调用链路
- `docs/DOMAIN.md`：核心业务对象、数据模型、生命周期
- `docs/CONVENTIONS.md`：长期有效的仓库约定与协作约束
- `docs/CHANGELOG_FOR_AI.md`：只记录会显著影响后续接手成本的变化
- `docs/README.md`：文档索引与阅读顺序

保持每个文件高信号，不要把它们写成大而全的改动流水账或完整代码文档。

在起草或重构这些文件前，先阅读 `references/templates.md`。

如果用户提供了稳定的通用约束，先阅读 `references/general-conventions.md`，再按类型分流：

- 代理执行约束、阅读顺序、硬约束入口规则，落到 `AGENTS.md`
- 代码结构、实现策略、长期协作约定，落到 `docs/CONVENTIONS.md`
- 如果与目标仓库现有规范冲突，以仓库现状和团队规则为准，不要强行覆盖

### 3. 打通入口文件

更新仓库入口文件，让后续会话无需重新审计即可发现这些文档：

- `AGENTS.md`：作为硬约束来源，并要求优先阅读 `docs/PROJECT_CONTEXT.md`
- 根目录 `README.md`：如果有助于发现入口，可增加简短的 AI 使用说明，但不要污染主 README
- `CLAUDE.md`：如果存在，尽量收缩成指向 `AGENTS.md` 的薄兼容层

如果 `CLAUDE.md` 里有独有规则，先迁移到 `AGENTS.md` 或 `docs/CONVENTIONS.md`，再收缩它。

### 4. 只写事实，不补猜测

起草项目上下文时：

- 标明哪些模块是真实活跃的
- 明确标出占位目录、脚手架区域或历史遗留壳子
- 区分用户可见功能与仅后端/基础设施能力
- 不要把文档、应用、包或功能写得比代码现状更成熟
- 修复你触碰到的失效链接

如果不确定，就回到源码核实，不要用泛化措辞把空白抹平。

### 5. 控制首读成本

为后续会话优化首读效率：

- 让 `PROJECT_CONTEXT.md` 成为首读主入口
- 让 `docs/README.md` 只承担索引职责，不再写成第二份项目概览
- 避免在 `CLAUDE.md`、`AGENTS.md` 和 `docs/*` 之间重复说明相同规则
- 把变更记录限制在真正影响后续接手成本的内容上

### 6. 收尾校验

结束前确认：

- 每个被引用的文件都真实存在
- 文档没有指向已经删除的路径
- `AGENTS.md` 与 `CLAUDE.md` 不会形成重复阅读回路
- 新增规则没有分散到多个相互竞争的来源中

## 交付标准

目标是让后续会话可以按下面的顺序进入项目：

1. 先读 `AGENTS.md`
2. 再读 `docs/PROJECT_CONTEXT.md`
3. 只打开当前任务需要的模块文件

如果仓库原本就有高质量文档，优先合并与收口，不要重复造一套新结构。

## 常见触发语

- “帮我给这个项目落一套 AI 首读文档”
- “把 AGENTS / CLAUDE / docs 整理成统一入口”
- “我不想每次新会话都重新调研项目，帮我初始化文档体系”
- “把这个仓库整理成后续模型容易接手的样子”
