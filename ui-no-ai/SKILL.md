# 专业界面设计与实现

把界面当作一张需要设计的完整画面：内容有主次，布局有比例，组件属于同一套语言，细节经过实际渲染后的修正。
减少模板感只是其中一项。删掉装饰、减少卡片、换一种颜色，都不能单独证明设计质量提高。

## 任务边界

- 遵守项目 `AGENTS.md`、平台要求和既有设计系统；有明确设计稿时优先保真还原。只评审时不修改文件；实现时保留真实业务能力。
- 页面级优化可以调整构图与层级，局部修改控制在相关区域。不要把一次按钮修改扩展为整页重构。
- 不伪造业务数据、评价、处理结果或产品承诺；不为展示效果改变费用、权限或操作后果。

## 开始前：建立视觉依据

查看目标页面及其相关组件、设计变量、图标和图片资源。改造已有页面时，优先取得当前渲染或截图，区分真实存在的问题与源码推测。

按以下来源建立依据：用户提供的参考 → 项目中完成度较高的同类页面 → 适合当前平台的成熟产品模式。需要外部参考时再查找，不为每次局部修改启动调研。

页面级新建或重设计，在能访问视觉资料时，选定适合当前任务的真实界面作为参照，并实际查看。优先比较相近的内容密度和交互复杂度，避免拿营销海报指导复杂工具；不要把多种互不协调的风格拼在一起。

参考要提取可实现的关系：主体占屏比例、文字和图片的节奏、控件密度、分组方式、底部操作的位置。不要只提取一个颜色或圆角。参考图的装饰也不意味着可以照搬其业务结构。

没有参考时，自主选择适合内容的方向并推进。审美选择通常不需要用户逐项决定；只在缺失信息会实质改变任务时询问。

## 先决定整屏怎么成立

页面级任务在写代码前，用简短、具体的描述确定以下决策，作为实现依据：

- **视觉中心**：用户第一眼应该看到哪个对象，以及它获得多大空间。
- **构图与密度**：主要区域怎样排列，哪些内容同组，哪里紧凑，哪里留出呼吸空间。
- **层级与风格**：靠尺寸、位置、字重、明暗中的哪些差异建立主次；哪些现有品牌元素值得强化。
- **操作路径**：主要动作放在哪里，次要动作如何收敛，滚动后如何继续操作。

“现代、简约、高级”不构成实现依据。应具体到“图片作为首屏主体；描述与尺寸设置组成紧凑编辑区；费用靠近底部制作按钮；帮助信息低于字段标签一个层级”。局部修改只需决定受影响的关系。

不同内容采用不同组织方式，以下用于判断，不是必套模板：

| 页面任务 | 优先组织的关系 |
| --- | --- |
| 图片、视频、创作工具 | 预览与编辑相邻，预览尺寸有存在感；控制区不挤压作品；提交、进度和成果各有清晰位置。 |
| 作品、商品、内容列表 | 图片比例和文字节奏一致；重要信息便于比较；筛选、数量、加载更多属于列表上下文。 |
| 业务后台 | 筛选、表格、批量操作形成连续工作区；列宽、数字和操作对齐；装饰不占据主要数据空间。 |
| 品牌、营销页面 | 标题、真实产品画面和行动入口共同构成首屏；后续内容围绕具体卖点展开，避免重复同一种区块。 |

## 把设计落实到可见细节

### 构图与空间

- 先确定内容边界、主轴和区域比例，再调整单个组件。桌面长文本需要合适的行宽；小屏优先保证主体和核心操作的可用空间。
- 建立连续的对齐关系：页标题、分组标题、字段和主要内容有共同基线。边缘错位必须有明确的层级或构图理由。
- 让间距表达关系：字段内部更紧，同组控件次之，不同任务区域更松。沿用项目间距变量；缺少变量时建立少量可复用的级差，避免逐元素随意取值。
- 分组按关系选择间距、底色、分隔线或卡片。作品和套餐可以有独立卡片；连续表单可以共享一个区域。检查边界是否重复，而不是统计卡片数量。
- 通过主体、局部密度和留白形成节奏。避免所有区域等大，也避免把内容全部挤到上半屏、下半屏只剩空白。

### 文字与信息层级

- 建立可辨认的页面标题、分组标题、正文和辅助信息层级，并适应实际内容；不要只把所有字都设成相近字号，再靠浅灰区分。
- 用字重和位置一起组织信息。价格、余额、数量等关键数字需要与单位、说明形成主次；不能把每个数值都做成海报标题。
- 用真实中文内容检查断行、行高、按钮宽度和多行截断。标题避免孤字换行，长说明不能把核心操作推出可用区域。
- 辅助信息仍需清晰可读。短句、明确动作和必要标签优先；费用、限制、风险与错误恢复信息必须保留。
- 逐条检查新增说明：是否帮助用户判断、避免出错或继续操作。删除泛泛宣传、重复字段或复述按钮的句子，保留有实际价值的帮助。

### 色彩、材质与资源

- 先安排页面底、内容面、主要文字、辅助文字和强调色的角色，再添加细节。沿用品牌主题；用面积和明暗控制重点，避免所有元素争夺注意力。
- 圆角随组件体量和角色保持协调；边框、底色、阴影各自承担分组或层级作用，避免为同一边界叠加多种强调。
- 使用有价值的图片、插画或产品预览提升表现力。优先已有真实资源，检查清晰度、裁切和比例；大面积占位框不能代替完成后的视觉设计。
- 图标统一来源、线宽和视觉尺寸，与文字光学对齐。默认不用 Emoji 充当功能图标；用户内容或表情产品本身的 Emoji 可以保留。
- 字体首先服从品牌、中文可读性和平台能力。颜色、字体、渐变、卡片本身都不是模板感的判据，关键是组合是否适合当前产品。

### 控件与操作

- 同类按钮、输入框、标签、列表行采用统一尺寸和状态语言；优先复用公共组件。调整局部样式不能导致相邻页面各成一套。
- 在同一决策区域明确主动作和次动作的权重。可点击元素要有辨识度，文字按钮和图标按钮也要保留可用的触摸区域。
- 覆盖本次操作涉及的加载、空、错误、禁用和选中状态；状态变化尽量保留布局稳定，防止按钮、列表或抽屉来回跳动。
- 动效用于反馈与空间连续性。检查相关的焦点、可访问名称、键盘遮挡、安全区与滚动，固定操作区应为内容留出位置。

## 用实际画面修正设计

功能验证与视觉验证分别判断。编译成功、操作可用、源码整齐，都不能替代对页面外观的检查。

页面级设计或明显的布局改造，在具备条件时查看目标平台的实际渲染或截图；小程序使用其开发者工具或对应截图，不能用 H5 效果冒充小程序验收。局部文案、单个样式调整按影响范围检查，不无条件执行整页重做或全量测试。

查看画面时按以下顺序处理问题：

1. **整屏**：第一眼的重点是否正确？主体是不是太小？是否头重脚轻、均匀堆块、留白失衡？先修区域比例和顺序。
2. **分组**：相关内容是否靠近？主要操作是否容易定位？边界和间距是否清晰？再修密度与层级。
3. **细节**：文字基线、边距、图标、圆角、裁切、长文本和状态是否协调？最后修局部质感。

把观察写成能执行的修改，例如“预览高度不足，被两段说明挤压；压缩说明区并增加预览可用空间”，不要只写“还不够高级”。修正后重新查看受影响的画面，直到没有明确可见的主要问题；不要为凑轮次做无依据的反复改动。

适配只检查项目支持的平台与相关尺寸。无法查看实际画面时，明确说明视觉效果尚未验证，不能仅凭代码宣称达到专业设计效果。

## 避免常见退化

- 只删标题、说明、卡片和颜色，剩下一个缺乏层次的普通表单。
- 只换主题色、加圆角或替换图标，保留原本失衡的布局。
- 每页都采用大标题、介绍语、三列卡片和底部行动区，无视页面实际任务。
- 用无关光球、渐变、毛玻璃或大量动效填补缺少构图的问题；或反过来把有价值的品牌表达全部清掉。
- 用整齐但空洞的占位内容验收，实际图片、长标题或错误信息一出现就失衡。

## 交付

实现任务交付实际代码，简要说明主要视觉变化和已执行的验证；评审任务给出具体位置、视觉问题及修改方式。不要输出长篇设计自评、审美分数或效果保证。审美完成度以可见结果接受检验。
